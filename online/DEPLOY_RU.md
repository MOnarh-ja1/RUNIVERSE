# Включение реальных Google-аккаунтов и мирового ТОПа RUNIVERSE

В репозитории готовы API (`online/server`) и шаблон `render.yaml`. **Публичный сервер ещё не создан и Google OAuth Client ID не получен.**

1. На https://console.cloud.google.com/ настройте Google Auth Platform (OAuth consent screen) и создайте OAuth client типа **Desktop app**. Для тестового режима добавьте нужные Google-аккаунты в список тестировщиков. Запишите **Client ID**, не client secret.
2. В Render создайте Blueprint из этого репозитория и файла `render.yaml`. Для постоянного хранения рекордов предусмотрен **persistent disk** — платный ресурс: проверьте стоимость и подтвердите создание самостоятельно. Значение `GOOGLE_CLIENT_ID` задайте в переменной окружения Render; не помещайте секреты в GitHub.
3. Дождитесь выдачи Render адреса `https://....onrender.com` и проверьте `/health` (должен отвечать `{"ok":true}`).
4. В GitHub обновите `online/public_config.json`: `{"api_base":"https://....onrender.com","google_client_id":"....apps.googleusercontent.com"}`.
5. Перезапустите MgameIO Launcher 1.2.0 и войдите через кнопку в профиле. OAuth откроется в системном браузере и вернётся по `http://127.0.0.1:<случайный порт>/callback` (Desktop app).
6. Проверьте, что после входа профиль показывает имя, а рекорды отправляются из **игры** на этот же API. Это отдельная интеграция: подготовленный лаунчер сам не отправляет результаты забегов.

Не публикуйте систему как безопасный соревновательный рейтинг до защиты от поддельных результатов и проверки соединения на Windows. Не используйте временный бесплатный диск для SQLite — рекорды могут пропасть.

Запуск реального публичного сервера требует доступа к облачному аккаунту и согласия с условиями хостинга; из кода в репозитории он не разворачивается автоматически.
